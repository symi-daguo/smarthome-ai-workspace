# 百宝箱工具与工程关联 —— 分析与实现记录

> 版本：1.0.4
> 诉求原文：「我们的百宝箱里面都有对应的工具，就是要相互关联起来，生成的图标位置都要允许修改，
> 每个智能百宝箱的内容如果跟对应的项目有关系就应该可以关联映射起来，
> 这样相互之间操作都能匹配到对应的工程中」

## 一、现状取证（改之前的事实）

### 1.1 百宝箱是一个「跳转目录」，不是工作台

`apps/web/src/pages/TreasureBox.tsx` 里每个工具只有一条 `to` 路由，
点一下就 `navigate(t.to)` 跳走。工具之间**没有任何数据通路**：

- 工具之间不知道彼此存在；
- 工具不知道自己在为**哪个项目**干活；
- 工具的产出不自动落到任何工程上。

### 1.2 方案侧早就有完整的产物归属字段

`PlanProject`（`apps/api/prisma/schema.prisma`）已存在这些字段，本次**没有新增任何表或字段**：

| 字段 | 含义 |
| --- | --- |
| `floorplanAssetId` | 户型底图 |
| `extraFloorplanAssetIds` / `floorplanFloors` | 第 2、3 张户型图与楼层名 |
| `renderAssetIds` / `renderAssetMeta` | 装修效果图（≤5）与分组元数据 |
| `videoAssetIds` / `videoTitles` | 场景视频（≤2）与标题 |
| `renderedFloorplanAssetId` | 精装修效果图 |
| `layoutPoints` | 点位数组（归一化坐标） |

结论：**归属机制早就有了，缺的是「工具能把产物送进去」的那条路。**

### 1.3 孤立的 `FloorplanLayout` 表

`FloorplanLayout`（schema.prisma:733）是「独立点位图纸」表，
有 `mediaAssetId` 与 `points`，但**没有 `planId`** ——
它与方案之间没有外键也没有业务关联。
`POST /api/layouts` 存的图纸，用 `GET /api/layouts` 能查到，但方案侧看不到它。

这正是「工具与项目不相通」在数据层的根因：
点位图画完了，方案不知道它存在，PPT 自然也用不上。

### 1.4 已有端点的能力边界

| 端点 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| `POST /api/plans` | 建方案时可带渲染图/视频 | 方案已存在时挂不了 |
| `PATCH /api/plans/:id/floorplan` | 挂户型图与点位 | 只管户型图这一类 |
| `PATCH /api/plans/:id/videos` | 挂视频（≤2） | 只管视频这一类 |
| `PATCH /api/plans/:id/assets` | **本次新增** | — |

## 二、本次做法（不造新轮子）

### 2.1 复用而不是新建

- **不新增表、不加字段**：产物归属继续用 `PlanProject` 上已有的字段。
- **不新造一套挂载协议**：`PATCH /api/plans/:id/assets` 内部按 `slot`
  分派到 `renderAssetIds` / `videoAssetIds` / `floorplanAssetId`，
  校验范式照抄既有的 `bindVideos`（素材必须属于本租户且 `status === 'ready'`）。
- **前端不写四遍**：抽 `AttachToPlanButton` 组件，
  生图页 / 生视频页 / 点位页共用同一个挂载入口与同一套报错文案。

### 2.2 「当前工程」是关联的连接点

新增 `apps/web/src/lib/currentPlan.ts`：把「正在做的方案 id」记在 localStorage。

为什么存 localStorage 而不是加表：
这是**当前正在做的活**的指针，不是业务数据。方案本身在服务端，
指针存的是 planId，换台电脑接着做不影响数据完整性。
决策阶梯里 YAGNI 排第一 —— 为「当前选中项」建表 + 迁移不划算。

它串起的是这条真实工作流：
`接单 → 建方案（选为当前工程）→ 百宝箱出图/出视频/布点位 → 产物挂进工程 → 导出 PPT`

### 2.3 工具侧的标记

`TreasureBox` 的每个工具新增 `attach` 字段，声明它的产物能挂到工程哪一处：

- `render`：出图类（生图、画布、彩平图、分区效果图…）
- `video`：出片类（灯光场景编排）
- `floorplan`：图纸类（点位布置、WiFi 热力、灯光点位）
- `none`：与方案无关（内容获客类、产品库、问诊）

带 `attach` 的工具在有当前工程时会携带 `planId` 跳转，工具页据此知道产物该往哪挂。

### 2.4 点位位置可改：拖拽 + 数值

点位图标**原本就支持拖拽**（`onPointerDownPoint`）。但拖拽只能到「大概位置」，
而点位图是要交给施工的 —— 差一点就装错地方。

所以在点位清单里补了 X/Y 百分比输入（步进 0.1%）：
拖拽定大方向，数值定精确位置，两条路都能改。

## 四、边界与未做

- **`FloorplanLayout` 表没有改**：它是独立图纸的历史功能。
  改它要动迁移与备份逻辑（`backup.controller.ts` 与 `agent.service.ts` 都引用了它），
  收益是「独立图纸也能挂方案」，而当前主路径是「从方案进点位板」，已覆盖主流程。
  保留原表不动，等确认独立图纸场景也要挂工程时再补 `planId`。
- **灯光场景编排页未接挂载按钮**：该页产出的是时间轴视频，
  与方案视频位（`videoAssetIds`）的语义不完全一致，贸然挂进去可能出错。
  已标记 `attach: 'video'`，待确认语义后再接。
- **`renderAssetMeta` 的空间归属**：挂上去的渲染图空间名为空，
  方案页的空间动线页会显示为「未分组」。这与「工具产出自动归位」还有差距，
  待方案页的分组交互确定后再补。
