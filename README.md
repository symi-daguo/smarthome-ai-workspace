# 智能家居 AI 工作台

面向智能家居服务商（门店老板、销售、设计师）的多租户 AI SaaS：一句话出方案 / 出图 / 出视频 / 出文案，交付可编辑 PPT，支持户型图布点与智能报价。

**开源自部署定位**：本项目让每个人都能在自己电脑上跑起来"自己玩"。模型由你自选——本地跑 ComfyUI / Ollama 等（配 config UI）或接任意 OpenAI 兼容的云端大模型 API；平台**不预设任何商业定价**，所有"额度扣费"单价由部署者按自己的模型成本通过环境变量配置（见下文「模型与计费配置」）。

规划背景与逐版本技术决策见 [增强型智能家居AI-SaaS平台规划文档.md](./增强型智能家居AI-SaaS平台规划文档.md)。

## 技术栈

- 后端：NestJS 12（ESM）+ Prisma 7 + PostgreSQL 18（pgvector）
- 前端：React 19 + Ant Design 6 + Vite 8
- 模型接入：对话走 OpenAI 兼容协议（可接任意国内外云端或本地 Ollama/LM Studio/vLLM）；生图支持 MiniMax `image-01` / OpenAI / 本地 ComfyUI；生视频支持 MiniMax（留空自动选 `T2V/I2V-01-Director`，可指定 `MiniMax-H3` 等带原生音轨的模型）或 OpenAI Sora；前端「模型配置」页**在线编辑、保存即生效**（DB 持久化，优先于 .env），含 provider 引导与连通性测试
- MiniMax 官方另有语音合成（`speech-2.6-hd` 等，`/v1/t2a_v2`）、音乐生成（`music-3.0`）、音色克隆与联网搜索能力，本项目**尚未接入**；已接入部分仅为上行的对话 / 图像 / 视频三类
- PPT 生成：pptxgenjs（MIT，浏览器端生成原生可编辑 16:9 幻灯片）

## 功能地图

### 账户与多租户
- 手机号注册 / 登录（用户协议与隐私政策勾选拦截）、注册即建租户并赠送演示额度
- 多租户隔离、RBAC 角色权限（超管 / 租户管理员 / 设计师 / 运营 / 只读）；**开源自部署默认最高权限**——注册用户即租户管理员，默认可完整配置模型（各人填自己的 API Key / 本地模型），会员与角色分级机制保留
- **会员与额度页**（`/vip`）：明确「开源免费自部署、注册即解锁全部能力、无需开通套餐」，列出已解锁能力清单与需要联系官方的三种情形（代运维 / 定制开发 / 发票合同）
- 统一 token 额度账本（当前已接入发放 / 消耗两种流水；充值、退还、邀请返点的枚举与界面已预留，支付通道接入后启用）、个人中心（额度总览、邀请码与返点说明、修改密码、退出）
- **个人中心统一承载设置**（侧栏「设置」直达 /tokens，无独立弹窗）：资料与偏好（昵称 / 头像底色 / 主题亮暗跟随系统）+ 数据备份与存储治理（全库 JSON 备份导出 / 产物占用统计 / 过期未引用产物清理）
- 亮色 / 暗色 / 跟随系统三态主题，**顶栏常驻切换**（额度胶囊旁），全站持久化；
  页面配色一律走 AntD 语义 token（`colorBgContainer` / `colorFillTertiary` / `colorBorder` 等），
  **不允许写死 `#fff` / `#F5F5F7` 这类浅色值**——深色主题下会变成突兀的浅色块

### AI 生成链路（真实接通，按额度扣费）
- 对话：按所选智能体人设注入 system prompt
- 生图：文生图 / 图生图，产物本地落盘 uploads 卷并入「我的资料库」；本次会话多图可左右翻页回看。
  - **参考图可上传，也可从「我的资料库」直接选**（与生视频首帧同源实现）
  - **适配视频**：出图统一按 16:9 且保持参考图构图，成图可直接当生视频首帧
  - **背景**：自动 / 纯白 / 透明（写进提示词约束）
  - **模型只读展示**「模型配置」页当前真实生效的模型，不提供选了不生效的下拉
- **AI 画布**（`/canvas`）：像聊天一样连续出图——多轮对话、每轮可出多个变体（重新生成**追加**不覆盖）、
  基于任一历史图派生新分支（`‹ 分支 N/M ›` 随时切回）、每轮标注「基于哪张图」、历史轮次可拉回输入框继续改。
  出图走后台异步作业 + 轮询，不长时间占连接。功能规格见 [replica/ai-canvas-spec.md](./replica/ai-canvas-spec.md)
- **WiFi 信号热力图**：上传户型图后**一键识别墙体**（Otsu 阈值 + 距离变换 + 连通域标记，
  纯前端确定性算法不调 AI），墙线可拖端点改方向、删除或手动补画；信号从设备四向扩散、
  **遇墙按系数衰减**，可设每墙衰减与有效信号阈值；填入图纸实际米数后得出比例尺，
  自动统计**覆盖率（㎡ 与百分比）**并在导出图上画摘要
- **智能方案全屏阅读器**：逐页翻阅，键盘 `←/→` `Home/End` `Esc` `F`，页码圆点可跳页，
  跟随系统「减少动态效果」自动关闭动画；**预算校验与档位预设**（基础/舒适/豪华/定制按面积推荐），
  配生态分配建议条，只提示不阻断
- **智能报价房间分组**：按房间聚合成可折叠分组，组序与行序均可拖拽（触屏可用，窄屏有上移下移按钮），
  户型图上可拖拽放置房间标签与报价行双向联动
- **圈选局部重绘**（AI 画布内）：在效果图上按住涂抹圈出要重做的区域，**圈外部分原样保留**；
  结果作为新变体出现，原图与原变体都不丢。需在「模型配置」把生图切到 OpenAI 兼容端点
  （走 OpenAI 的 images/edits 端点），其它 provider 会明确拒绝而不是整张重画
- **生视频音轨**：静音 / 仅音效 / 仅音乐 / 音效＋音乐，写进画面描述交给模型生成；
  明确提示当前模型是否真的支持出声，不让用户误以为选了就有声
- 工作台**智能意图识别**：边输入边识别你要去的板块（生图 / 生视频 / 方案 / 报价 / 资料库 / 知识库），
  给出可点的「前往」建议，问句与闲聊不打扰；不做发送即跳转，不劫持对话
- 生视频：上传首帧图（或从「我的资料库」选择）做图生视频，也可纯文字描述生成；时长/画质/比例可调
- 智能方案：LLM 生成 9 页标准方案（封面 / 品牌实力 / 空间动线 / 需求洞察 / 生态规划 / 场景×2 / 预算 / 交付），逐页审稿编辑（版本递增）+ 每页讲解稿，**交付真 .pptx（文本 / 图表 / 形状全部原生可编辑）** + 完整讲稿 + 全屏播放 + 免登录分享链接（客户微信直开）；幻灯片按 jingmei-ppt 方法论设计，8 类页型独立构图 + 每页实景配图 + 阴影卡片层次 + 预算原生可编辑条形图 + 交付流程形状

### 接单工作台（AI 接待）
- 粘贴客户微信原话 / 电话纪要，AI 自动解析建档并按需求从产品库推荐关注品类与候选设备
- **结构化采集**（下游方案与报价的唯一输入，不靠自由文本猜）：客户与房屋（含装修阶段 6 档）、生活需求细分（常住成员 / 优先需求 ×3 / 明确不做 / 控制习惯 / 睡前夜间 / 已有设备偏好）、**客户想体验的 10 个场景**、**9 类系统的三态矩阵**（是否需要 + 应用区域 + 具体配置）、**预算起点 / 上限 / 包含范围**。AI 解析会一并抽取这些结构化字段，但**未提及的系统一律不猜**
- 状态机推进：了解客户 → 需求确认 → 方案匹配（可挂接已生成的智能方案）→ 报价 → 成单 / 失单（可重新激活），非法跳跃被拒绝
- 跟进记录时间线 + AI 跟进建议（下一步动作与话术要点），接待列表按状态分组持久化

### 其他
- 短视频工作台（IP 档案访谈式）、使用指引弹窗
- **全局返回**：顶栏「← 返回」按钮覆盖所有子页面；素材预览等二级视图均为应用内弹窗可返回，不发生离开应用的页面跳转
- 全站**流式响应式**（768 → 1440 → 1920 → 4K 2560+）：内容区卡片随视口等比拉宽铺满，**不设固定封顶、不出现两侧大片留白**；功能页统一 PageHeader + 双栏卡片网格布局标准；界面图片资产本地化，无外部链接依赖
  - 实现要点：双栏页面的**主区容器必须显式 `flex: 1` + `minWidth: 0`**。在 AntD `Layout` 的 flex 行里，缺少 `flex-grow` 的容器会退化成内容宽度，视口多出来的部分全部变成右侧空白；`minWidth: 0` 则保证 flex item 能收缩到内容宽度以下而不是被内容撑开
  - 窄栏用**像素**而不是断点百分比：AntD 栅格 `lg={7}` 是固定比例，1920px 下左栏会占到 29%（约 472px），比窄栏设计意图宽出一倍

## 快速开始

```bash
cp .env.example .env          # 填入你的模型 key 与密钥（见下）
docker compose up -d db # 或使用本机 postgres
pnpm install
pnpm db:migrate
pnpm db:seed
pnpm dev                      # web 5173 + api 3080
pnpm build && pnpm smoke      # 冒烟基于编译产物
```

一键容器部署（含自动 migrate + 幂等 seed）：

```bash
docker compose up -d --build  # web 5173、api 3080
```

### 构建期网络配置

项目 `.npmrc` **刻意不固定 registry**，默认走官方源 `registry.npmjs.org`——这是 CI 与海外部署的正确选择。
国内网络构建慢或偶发抖动时，用构建参数切到镜像源，**不需要改仓库任何文件**：

```bash
NPM_REGISTRY=https://registry.npmmirror.com/ docker compose up -d --build
```

该变量由 compose 的 `build.args` 透传给 Dockerfile 的 `ARG NPM_REGISTRY`，仅作用于构建期，不进镜像、不影响运行时。

除此之外已内置三层防护，无需额外配置：

| 防护 | 作用 | 实测依据 |
|---|---|---|
| 网络退避重试 | registry 抖动（`error 23` / `ECONNRESET`）时自动重试 5 次，退避 20s→120s | 原故障即此类，重跑即恢复 |
| BuildKit pnpm store 缓存 | 依赖持久保留，重建时命中缓存不必全量重下 | 二次构建 258 个包**全部复用、零下载**，26.9s vs 冷构建约 2min |
| 供应链发布窗口 `minimumReleaseAge: 1440` | 新发布版本需满 24 小时才可安装，压缩投毒窗口 | 784 个条目全部通过校验 |

> `minimumReleaseAge` 取 24 小时而非 7 天是实测结论：本项目 Vite 8 / Rolldown 迭代极快，
> 7 天窗口会拒掉 `@rolldown/binding-*` 1.2.13、`@napi-rs/canvas` 1.0.11 等近 7 天发布的包并**直接打断构建**。
> 未设 `minimumReleaseAgeExclude`，即没有无效豁免；日后安装刚发布的版本会被明确拦下并提示。

## 模型与计费配置

登录后侧栏「系统管理 → 模型配置」页可**在线完成全部模型配置**：对话 / 生图 / ComfyUI / 生视频四张可编辑卡片（Base URL、API Key、模型、provider 选择、ComfyUI 地址与工作流节点映射），保存即生效、持久化到数据库（无需重启）；「选用」按钮一键填入 DeepSeek / 通义千问 / 智谱 / Kimi / OpenAI / MiniMax / Ollama / LM Studio / vLLM 的推荐地址与模型；每卡带连通性测试与「恢复 .env 默认」。API Key 保存后只回显末四位，绝不外传明文。

`.env` 仅作为**部署默认值**（DB 未配置或点「恢复 .env 默认」时生效）：

```bash
# —— 对话：OpenAI 兼容协议，接任意国内外云端或本地模型 ——
# 不设置 LLM_* 时回退 MiniMax_*（向后兼容）
LLM_BASE_URL=https://api.deepseek.com          # 或 https://dashscope.aliyuncs.com/compatible-mode/v1、智谱、Kimi、OpenAI、http://localhost:11434/v1(Ollama) …
LLM_API_KEY=你的key                              # 本地 Ollama/LM Studio 填任意占位串
LLM_MODEL=deepseek-chat                          # 可选：锁定模型；留空跟随请求
MiniMax_BASE_URL=https://api.minimaxi.com/v1     # 默认 provider（LLM_* 未设时生效）
MiniMax_API_KEY=你的key

# —— 生图：minimax(默认) | openai | comfyui(本地) ——
IMAGE_PROVIDER=comfyui
COMFYUI_BASE_URL=http://127.0.0.1:8188
COMFYUI_WORKFLOW_PATH=./comfyui-workflow.json    # 项目内置 SD1.5 模板，可换成自己导出的工作流
```

## 知识库联动：优势与场景

客户电脑性能足够时，可拉取最新仓库自行部署专业知识库引擎（[WeKnora](https://github.com/Tencent/WeKnora)：git clone → docker compose up -d；Obsidian：安装 Local REST API 插件），在「我的知识库」页填地址与 Key 即可联动。相比平台内置的轻量资料库，外部引擎带来：

- **更强的检索**：WeKnora 提供向量 + BM25 混合检索、GraphRAG、多文档格式解析（PDF/Word/Excel/图片 OCR），Obsidian 直读你的全部笔记库——资料规模越大、格式越杂，优势越明显
- **对话更准**：工作台对话自动检索客户私有资料注入上下文，回答引用你的产品手册与话术，而非通用模型泛泛而谈
- **接单更懂行**：AI 解析客户描述时能命中你资料库中的品牌、型号与报价规则，建档即带业务口径
- **数据主权 + 零锁定**：知识只存在客户自己的引擎里，平台仅经 REST 实时检索、不落副本；检索失败自动降级为无知识库模式，绝不阻塞主链路；每次检索写审计日志（场景 + 命中数），权限按租户与角色隔离

## 安全、限流与数据治理

- 限流 env 可配：全局 `RATE_LIMIT_GLOBAL`（默认 300/分钟/IP）、注册 / 登录 `RATE_LIMIT_AUTH`（默认 10/分钟，防暴力破解）
- `trust proxy` 已开启，nginx 反代后限流按真实客户端 IP 计数
- 生产环境（`NODE_ENV=production`）：默认 JWT 密钥 / 默认管理员密码启动直接拒绝；Swagger 文档关闭
- 额度扣减在数据库事务内原子完成（`updateMany` 余额条件 + 账本写入），并发无超扣竞态
- 文件流路径穿越防护、上传 MIME + 大小校验、多租户资源隔离、密钥仅经环境变量注入不入库
- **数据备份**：个人设置「导出全库数据备份」→ `GET /api/admin/backup` 导出全部 28 表 JSON（同时在 `uploads/backups/` 留底）；产物文件在 `api-uploads` 卷、数据库在 `pgdata` 卷，迁移时连同两个 docker volume 一起备份即可完整恢复
- **磁盘治理**：`docker-compose` 已配 json-file 日志轮转（10MB×3）防日志挤爆磁盘；产物配额 `UPLOAD_QUOTA_MB`（默认 4096），个人设置可查看占用并一键清理 30 天前且未被方案/布局引用的过期产物
- **升级不丢数据**：数据全在 `pgdata` / `api-uploads` 两个命名卷，`docker compose up -d --build` 重建镜像不影响卷；nginx 对 `index.html` 禁缓存（hash 资源 immutable），发版后浏览器不会加载到失效 chunk

## 开发规范

- 回复与注释使用中文，不使用 emoji
- 决策阶梯：YAGNI → 复用 → 标准库 → 原生 → 已装依赖 → 一行 → 最少实现
- 提交前必须：`pnpm typecheck && pnpm build && pnpm smoke` 全绿
- 新增依赖需许可证检查（MIT / Apache-2.0 / BSD 优先，禁止 GPL / AGPL）

### 关于「完成」的判定口径

`smoke` 只证明 **HTTP 契约**正确（校验、权限、幂等、落库、参数是否真正传到出图层），
**证明不了界面**。本项目曾因此把「开始接单」标成完成，实际缺了 5 处结构化采集，
而 222/222 全绿、typecheck 全过、数据层完全正确 —— 三道门禁全部看不出来。

因此本仓库统一：

- 功能矩阵里的 `✅` 只代表**已打开界面逐屏核对通过**；仅代码 / 契约层面确认的一律标 `🔸`
- 改任何影响界面呈现的代码前**必须先截图取证**；截图不可信时以 DOM 的 inline style 为准
  （本机浏览器截图工具出现过复用同一帧缓存的情况，连续多帧字节完全相同）
- 每轮迭代的逐板块核对结论落在 [`replica/audit-2026-10-13.md`](./replica/audit-2026-10-13.md)，
  含**未验证项**与**验证方法的边界**，避免下一个人拿可疑证据下结论
