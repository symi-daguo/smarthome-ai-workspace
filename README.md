# 智能家居 AI 工作台

给智能家居门店用的一套 AI 工作台：把客户的需求变成**可交付的方案、效果图、视频和报价单**，
交到客户手上，方案还能在 PPT 里继续改。

**它怎么收费**：不收费，也没有充值、套餐、会员这一套。
你用自己的模型账号（或者跑在自己电脑上的模型），数据都存在你自己的机器上。
算力开销只在服务端记账，界面上不摆任何计费入口 —— 它不是付费门槛，也不该被看成一个门槛。

**它怎么部署**：下载桌面版双击即用；或者用自己的服务器跑 Docker。
这是**开源自部署**软件，不是别人托管的云服务：你的客户资料、你的报价单，始终在你手上。

---

## 这个项目解决什么问题

门店的活是碎的：客户在微信上说了半天需求，你得记下来；方案要画出来；效果要给客户看；
视频要剪；最后还得报价。传统做法是**在五个工具之间搬数据**——
聊天记录抄进表格、表格贴进 PPT、效果图丢进网盘、报价单另开一个 Excel。
数据一搬就错，版本也对不上。

这个工作台把这条链路**接成一条**：客户的原话进来，出来的是一份能改的方案、
配套的效果图与视频、以及一张算过价的报价单，中间不用你手动搬。

它也把**「素材从哪来」这件事**交给你自己的 Agent：
产品的批量整理、同行的热门内容采集，这些「要到外面取数」的活，
系统给出一份机器可读的**格式契约**，你的 Agent 照着它取数、按格式整理、提交进来。
系统不替你爬别人的站，也不替你登录任何平台。

## 优势

**一条链路走完交付，不用在工具之间搬数据**
接单时把客户原话粘进去就能建档；方案一页页生成、可编辑；效果图、场景视频、灯光方案、
点位图、报价单全部引用同一份需求与产品库，不会出现「报价单上的产品跟方案里对不上」。
上传户型图后可由模型读图识别房间、按空间标准配置自动落位，**每个标记都落在它该在的房间里**，
方案师再逐个微调。交付物可导出 PPTX 与**高清 PDF**（矢量、页序与 PPT 一致），客户分享链接也能自己导。
这一整条链路由你的 Agent 串起来（见「让 Agent 来管理它」），界面负责看结果、改结果。

**模型完全是你自己的**
对话走 OpenAI 兼容协议，任意云端或本地端点都能接（本地 Ollama / LM Studio / vLLM 直接填地址）。
生图支持三家主流服务与 ComfyUI（**本机实例和云端实例都行**），生视频支持两家。
密钥存在你自己的库里，**也能在网页上随时改**（保存即生效，带连通性测试）。

**数据完全是你自己的**
多租户隔离，员工各看各的租户；资料库、报价单、客户记录都在你的机器上；
全库 JSON 备份可导出、可恢复；产物有配额上限与过期清理，不会悄悄撑爆磁盘。

**可以让 Agent 接管**
系统对外提供 **165 条操作的能力清单**（19 个分组），你的 Agent 读一次清单就知道能做什么、
每条要什么权限、哪些会删数据 —— 比让它读源码省一两个数量级的 token。
写操作全部落审计（存请求体摘要不存明文），破坏性操作前自动打快照、出错可一键还原。

**不设付费墙**
注册即解锁全部能力，不存在开通套餐、也没有付费等级。
角色分级机制保留，但**权限由岗位决定，与付不付钱无关**。
算力开销由部署者自己承担、自己配置，界面不展示余额、不展示单价、不做「额度不足」的拦截。

**有桌面版**
不想装 Docker、不想配数据库，就下载 `.dmg` 双击即用：
内嵌 PostgreSQL + 本地 API + 前端打包成一个应用，数据落在你自己的电脑上，不出本机。

**质量有闸门**
每次发布前跑完五条工程闸门：类型检查、构建、**500+ 条端到端冒烟断言**、
Markdown 渲染检查、品牌与合规检查，全绿才允许提交。
公开仓库的 CI 每次 push 都会在干净环境里重跑一遍。

## 快速开始

### 一、桌面版（最省事，macOS Apple Silicon）

1. 到 [Releases 页面](https://github.com/symi-daguo/smarthome-ai-workspace/releases) 下载
   `智能家居AI工作台-1.0.2-arm64.dmg`（约 216MB，Apple 公证已通过）
2. 双击挂载，把「智能家居AI工作台」拖进「应用程序」
3. 打开它，用默认账号登录：`13800000000` / `Admin@123456`
4. 进「系统管理 → 模型配置」，填上你自己的模型接口（填完点「连通性测试」确认通）
5. 回到工作台，就可以开始出方案了

桌面版的数据在你的用户目录下（`~/Library/Application Support/智能家居AI工作台/`），
想换机器时在「个人中心 → 令牌与备份」导出全库 JSON 备份即可。

### 二、Docker 部署（自己的服务器）

```bash
git clone https://github.com/symi-daguo/smarthome-ai-workspace.git
cd smarthome-ai-workspace
cp .env.example .env      # 至少改三处，见下
docker compose up -d --build
```

起来之后：前端 `http://<你的域名>:5173`、API `http://<你的域名>:3080`。
容器启动时自动执行数据库迁移与种子数据，**不需要你手动跑任何数据库命令**。

### 三、部署前必填三项（漏了容器会拒绝启动）

```bash
cp .env.example .env

# 1) JWT 签名密钥 —— 必须改。默认值是公开的（人人可查），拿到就能伪造登录 token
echo "JWT_SECRET=$(openssl rand -hex 32)" >> .env

# 2) 第一个管理员账号（手机号 + 密码），用默认密码等于没有密码
sed -i.bak "s/^SEED_ADMIN_PHONE=.*/SEED_ADMIN_PHONE=你的手机号/" .env
echo "SEED_ADMIN_PASSWORD=$(openssl rand -base64 18)" >> .env

# 3) 模型 Key —— 对话模型（LLM_API_KEY 或 MiniMax_API_KEY）至少填一个
echo "LLM_API_KEY=你的模型key" >> .env
```

这三项在 `.env.example` 里**故意留空**，所以 `docker compose up` 会直接报错停下，
而不是带着弱默认值跑起来 —— 这是开源自部署必须守住的第一道门。

本地开发（不装 Docker）：

```bash
cp .env.example .env && pnpm install
docker compose up -d db
pnpm db:migrate && pnpm db:seed
pnpm dev            # web 5173 + api 3080
pnpm build && pnpm smoke   # 冒烟跑的是编译产物
```

界面负责**管理与查看**：资料、产品、报价、点位、情报、团队，这些直接在里面做。
**生成类动作**（接单建档、方案文案、效果图、场景视频、结构化提取、产品批量补全）
一律由你的 Agent 调接口完成 —— 服务端接口一个不少，只是界面上不摆这些按钮，
避免把「点一下就产生模型开销」摆在日常操作位上。

### 遇到问题先看这张表

| 你看到的现象 | 多半是什么原因 | 怎么办 |
|---|---|---|
| 生成方案一直转圈 | 模型接口没通，或响应特别慢 | 「模型配置」点连通性测试；超时会明确提示，等约 4 分钟封顶 |
| 出图或出视频报错 | 模型 Key 没填或填错 | 「模型配置」里填 Key，再点连通性测试 |
| 提示模型账户额度不足 | 你自己的模型服务方给的额度用完了 | 换一个模型 Key，或换本地模型端点 |
| 提示连不上模型服务 | 网络或服务地址填错了 | 「模型配置」核对地址；本地模型要填本机端口 |
| 上传的中文文件名显示成乱码 | 1.0.0 及更早版本的问题 | 升级到 1.0.1 或更高；已传过的旧记录删掉重传一次 |
| 忘了密码 | — | 侧栏「个人中心」里改 |

## 让 Agent 来管理它

这个系统**本来就是给 Agent 用的**：对外是一套完整的 HTTP API，
每条操作都声明了所需权限、标注了会不会删数据。Agent 不用读源码，读一次能力清单就能上手。

### 你的 Agent 能直接做什么

- **批量整理产品库**：去品牌官网取产品清单 → 按格式契约整理 → 提交导入
  （契约里有字段清单、取值范围、当前可用的品类字典、CSV 模板与 JSON 示例，
  界面可下载，也可让 Agent 直接调 `GET /api/products/import-format` 取同一份）
- **每天盯对标账号**：按采集契约登录平台、抓热门内容的元数据、提交回来；
  服务端算热度分、做 AI 映射分析，产出风格画像与「我们差在哪、该拍什么」的差距清单
- **跑日常对账**：查算力开销流水、拉审计记录、导出报价与产品做二次加工
- **接进你自己的系统**：小程序、ERP、内部工具都能直接调，不需要为它单独开发一套接口

### 技能包：给智能体现成的说明书

两处都能拿到，内容同源：

- **仓库里**：[Agent接入指南.md](./Agent接入指南.md) —— 认证、权限、幂等、快照、错误码与接入自检步骤
- **界面里**：登录后进「系统管理 → 模型配置」，页面底部有「Agent 集成技能包（Skill Pack）」，
  点「复制技能包（Markdown）」直接拿走。里面除了接入说明，还带当前生效的模型配置摘要
  （**不含任何 Key**），以及能力清单、对标情报等**全部板块**的端点与调用方式。

也可以让 Agent 自己拉：`GET /api/admin/model-config/agent-skillpack`（返回 Markdown 文本）。

### 三步接入

**1）建机器账号 + 签发 API Key**

```bash
# 建机器账号（无可用密码，只能用 Key 登录），权限完全走现有 RBAC
curl -X POST http://127.0.0.1:3080/api/agent/service-accounts \
  -H "Authorization: Bearer <你的登录 token>" -H 'Content-Type: application/json' \
  -d '{"name":"数据分析 Agent","roleKey":"viewer"}'

# 签发 Key（只返回一次，平台不存密钥材料）
curl -X POST http://127.0.0.1:3080/api/agent/keys \
  -H "Authorization: Bearer <你的登录 token>" -H 'Content-Type: application/json' \
  -d '{"name":"ci-runner","ttlDays":90,"serviceAccountId":"<服务账号 id>"}'
```

Key 本身是一枚用 `JWT_SECRET` 签名的 JWT，库里只留可吊销的记录 ——
**数据库整体泄露也推不出可用凭证**。之后所有请求直接 `Authorization: Bearer <Key>`，
认证、权限、多租户全部沿用现成链路。

**2）读能力清单**

```bash
curl -H "Authorization: Bearer <API Key>" \
  'http://127.0.0.1:3080/api/agent/manifest?effective=1'
```

`effective=1` 是 Agent 的正确入口：**按调用者权限过滤，只列真正调得动的**。
不按权限过滤的话，一个只读 Key 读到的清单也会显示「可以删产品」，
Agent 就会照着错的预期反复撞 403，既烧 token 又烧轮次。

**3）调接口**

```bash
curl -X POST http://127.0.0.1:3080/api/benchmark/contents \
  -H "Authorization: Bearer <API Key>" -H 'Content-Type: application/json' \
  -d '{"batchId":"collect-2026-10-21","items":[{"accountId":"<账号 id>","title":"...","text":"...","sourceUrl":"..."}]}'
```

### 两道安全网

- **全量审计**：所有写操作自动落库，记谁（人点的 `USER` 还是机器跑的 `AGENT`）、
  什么时间、哪个接口、什么状态码、耗时多久、请求体的 SHA-256 摘要
  （**存摘要不存明文** —— 报价单与接单记录里全是客户姓名电话）。
  客户端带 `X-Request-Id` 可把一串动作串成一次任务复盘。
- **操作前快照与还原**：破坏性操作（DELETE 等）在调用方没自带 `X-Snapshot-Id` 时，
  拦截器会**先自动打一份快照再放行**。出问题时一键还原到操作前。
  注意边界：快照只还原**数据库里的行**，已经消耗掉的算力、已经生成出来的图片视频撤不回。

清单与代码之间有**双向漂移检查**守着：新增接口忘了写进清单 → 门禁 FAIL；
清单写了代码里没有的路由 → FAIL；声明的权限与实际守卫不一致 → FAIL。

完整接入细节见 [Agent接入指南.md](./Agent接入指南.md)。

## 参与迭代

**这个项目欢迎你直接用，也欢迎你提意见。**

我们把它开源出来，是想让它长成**门店真的愿意天天用的样子** ——
而只有真正用起来的人，才知道哪一步别扭、哪句话看不懂、哪个功能还差一口气。

- **试了觉得哪里别扭**：开个 Issue 说一声就行，不必写得很正式，一句话「导出的时候日期格式不对」也很有用
- **想要的功能**：同样开 Issue 讲场景（你想解决什么），比讲实现方式更容易被采纳
- **踩到坑了**：Bug 也欢迎报，附上现象和你的版本号，我们复现后会修
- **想一起改**：Fork 提 PR 即可。我们会认真看，有分歧的地方会来讨论

每一版改了什么，都写在迭代记录里（大白话，不讲代码）：
