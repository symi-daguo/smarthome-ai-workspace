# 智能家居 AI 工作台

面向智能家居服务商（门店老板、销售、设计师）的多租户 AI SaaS：一句话出方案 / 出图 / 出视频 / 出文案，交付可编辑 PPT，支持户型图布点与智能报价。

**开源自部署定位**：本项目让每个人都能在自己电脑上跑起来"自己玩"。模型由你自选——本地跑 ComfyUI / Ollama 等（配 config UI）或接任意 OpenAI 兼容的云端大模型 API；平台**不预设任何商业定价**，所有"额度扣费"单价由部署者按自己的模型成本通过环境变量配置（见下文「模型与计费配置」）。

规划背景与逐版本技术决策见 [增强型智能家居AI-SaaS平台规划文档.md](./增强型智能家居AI-SaaS平台规划文档.md)。

## 技术栈

全部为 **2026 年当前最新稳定版**（逐个取自 registry `dist-tags` 实测，不凭印象）。
两处**刻意不升到最新**的，理由见「依赖安全」与下方注释：

- 后端：NestJS 12.1.3（ESM）+ Prisma 7.10.1 + PostgreSQL 18.6（pgvector）
- 前端：React 19.3.1 + Ant Design 6.6.6 + Vite 8.3.4
- 语言：TypeScript **6.0.3**（不是最新 7.0.2：`@nestjs/swagger@12.0.2` 的 peer 是
  `^5.5.0 || ^6.0.0`，且微软官方声明 7.0 没有稳定编程式 API、内嵌 TS 的工具链要等 7.1）
- 构建：pnpm **11.28.6**（不是最新 12.14.0：pnpm 12 拒绝在 corepack 下运行，
  且会把自己的平台二进制写进项目 lockfile）
- 部署镜像：Node **24.22.0**-alpine（当前 LTS 最新）、nginx **1.30**-alpine（稳定线；奇数版是 mainline）
- 模型接入：对话走 OpenAI 兼容协议（可接任意国内外云端或本地 Ollama/LM Studio/vLLM）；生图支持 MiniMax `image-01` / OpenAI / ComfyUI（**本机与云端实例均可**，云端填 API Key 走 Bearer 鉴权）；生视频支持 MiniMax（留空自动选 `T2V/I2V-01-Director`，可指定 `MiniMax-H3` 等带原生音轨的模型）或 OpenAI Sora；前端「模型配置」页**在线编辑、保存即生效**（DB 持久化，优先于 .env），含 provider 引导与连通性测试
- MiniMax 官方另有语音合成（`speech-2.6-hd` 等，`/v1/t2a_v2`）、音乐生成（`music-3.0`）、音色克隆与联网搜索能力，本项目**尚未接入**；已接入部分仅为上行的对话 / 图像 / 视频三类
- PPT 生成：pptxgenjs（MIT，浏览器端生成原生可编辑 16:9 幻灯片）

## 功能地图

### 账户与多租户
- 手机号注册 / 登录（用户协议与隐私政策勾选拦截）、注册即建租户并赠送演示额度
- 多租户隔离、RBAC 角色权限（超管 / 租户管理员 / 设计师 / 运营 / 只读）；**开源自部署默认最高权限**——注册用户即租户管理员，默认可完整配置模型（各人填自己的 API Key / 本地模型）。角色分级机制保留，但**不设任何付费等级**：权限由角色决定，与付费无关
- **开源说明与额度页**（`/quota`，原 `/vip` 已改名并保留旧路由重定向）：明确「开源免费自部署、注册即解锁全部能力、无需开通套餐」，列出已解锁能力清单与需要联系官方的三种情形（代运维 / 定制开发 / 发票合同）
- 统一 token 额度账本（当前已接入发放 / 消耗两种流水；充值、退还、邀请返点的枚举与界面已预留，支付通道接入后启用）、个人中心（额度总览、邀请码与返点说明、修改密码、退出）
- **个人中心统一承载设置**（侧栏「设置」直达 /tokens，无独立弹窗）：资料与偏好（昵称 / 头像底色 / 主题亮暗跟随系统）+ 数据备份与存储治理（全库 JSON 备份导出 / 产物占用统计 / 过期未引用产物清理）
- 亮色 / 暗色 / 跟随系统三态主题，**顶栏常驻切换**（额度胶囊旁），全站持久化；
  页面配色一律走 AntD 语义 token（`colorBgContainer` / `colorFillTertiary` / `colorBorder` 等），
  **不允许写死 `#fff` / `#F5F5F7` 这类浅色值**——深色主题下会变成突兀的浅色块。
  **判断口径**：压在**界面容器**上（卡片 / 面板 / 页面底 / 提示框）的颜色一律走 token；
  压在**图片或画面之上**做标记的颜色（播放头、色温光晕、时间码胶囊）刻意写死并抽成具名常量 +
  注明理由，因为它们明暗两套主题下都要醒目——否则下次审查会被当成漏改项再扫一遍。
  0.1.52 按此口径全站扫了 18 条路由，结论见 [audit §6.5](./replica/audit-2026-10-13.md)

### AI 生成链路（真实接通，用你自己配置的模型）
- 对话：按所选智能体人设注入 system prompt
- 生图：文生图 / 图生图，产物本地落盘 uploads 卷并入「我的作品」；本次会话多图可左右翻页回看。
  - **参考图可上传，也可从「我的作品」直接选**（与生视频首帧同源实现）
  - **适配视频**：出图统一按 16:9 且保持参考图构图，成图可直接当生视频首帧
  - **背景**：自动 / 纯白 / 透明（写进提示词约束）
  - **模型只读展示**「模型配置」页当前真实生效的模型，不提供选了不生效的下拉
- **AI 画布**（`/canvas`）：像聊天一样连续出图——多轮对话、每轮可出多个变体（重新生成**追加**不覆盖）、
  基于任一历史图派生新分支（`‹ 分支 N/M ›` 随时切回）、每轮标注「基于哪张图」、历史轮次可拉回输入框继续改。
  出图走后台异步作业 + 轮询，不长时间占连接。功能规格见 [replica/ai-canvas-spec.md](./replica/ai-canvas-spec.md)
- **WiFi 信号热力图**：上传户型图后**一键识别墙体**（Otsu 阈值 + 距离变换 + 连通域标记，
  纯前端确定性算法不调 AI），墙线可拖端点改方向、删除或手动补画；信号从设备四向扩散、
  **遇墙按系数衰减**，可设每墙衰减与有效信号阈值；填入图纸实际米数后得出比例尺，
  自动统计**覆盖率（㎡ 与百分比）**并在导出图上画摘要
- **智能方案全屏阅读器**：逐页翻阅，键盘 `←/→` `Home/End` `Esc` `F`，页码圆点可跳页，
  跟随系统「减少动态效果」自动关闭动画；**预算校验与档位预设**（基础/舒适/豪华/定制按面积推荐），
  配生态分配建议条，只提示不阻断
- **智能报价房间分组**：按房间聚合成可折叠分组，组序与行序均可拖拽（触屏可用，窄屏有上移下移按钮），
  户型图上可拖拽放置房间标签与报价行双向联动
- **圈选局部重绘**（AI 画布内）：在效果图上按住涂抹圈出要重做的区域，**圈外部分原样保留**；
  结果作为新变体出现，原图与原变体都不丢。需在「模型配置」把生图切到 OpenAI 兼容端点
  （走 OpenAI 的 images/edits 端点），其它 provider 会明确拒绝而不是整张重画
- **生视频音轨**：静音 / 仅音效 / 仅音乐 / 音效＋音乐，写进画面描述交给模型生成；
  明确提示当前模型是否真的支持出声，不让用户误以为选了就有声
- 工作台**智能意图识别**：边输入边识别你要去的板块（生图 / 生视频 / 方案 / 报价 / 资料库 / 知识库），
  给出可点的「前往」建议，问句与闲聊不打扰；不做发送即跳转，不劫持对话
- 生视频：上传首帧图（或从「我的作品」选择）做图生视频，也可纯文字描述生成；时长/画质/比例可调
- 智能方案：LLM 生成 9 页标准方案（封面 / 品牌实力 / 空间动线 / 需求洞察 / 生态规划 / 场景×2 / 预算 / 交付），逐页审稿编辑（版本递增）+ 每页讲解稿，**交付真 .pptx（文本 / 图表 / 形状全部原生可编辑）** + 完整讲稿 + 全屏播放 + 免登录分享链接（客户微信直开）；幻灯片按 jingmei-ppt 方法论设计，8 类页型独立构图 + 每页实景配图 + 阴影卡片层次 + 预算原生可编辑条形图 + 交付流程形状
  - **第 1 步素材区**：户型图最多 3 张（逐张标楼层，PDF 需先按页拆图）+ 装修效果图最多 5 张（按实际空间分组，同一空间只允许一张代表图作为主视觉）+ 补充需求与服务资料 9 项（预算来源、明确不做的项目、真实案例依据等）
  - **页数按素材算**：沟通模块 + 额外户型图 + 素材展示页 = 下限，提交时真按下限夹取，不会「界面说 11 页、交付 9 页」
  - **户型图 → 精装修渲染**：传平面图后按方案风格与生态生成顶视精装图（22 秒级），渲染图上**自动叠加你布好的设备点位**，与分享页 / PPTX 同一份合成像素
  - **交付三件套**：PPTX + 完整讲稿 + 图片包（户型图 / 精修图 / 效果图原图）打成一个 zip，文件名由服务端给定（`方案名-V3-交付三件套.zip`），2 小时内有效的签名直链下载，**方案改版后旧链接自动失效**，不会把旧版文件发给客户
  - **交付前预检**：逐页点名「还有『待确认』这类内部语句」，指到第几页哪个字段，由门店决定改还是删（不静默净化，也不硬拦）
  - **交付模版（两套，各 3 选 1）**：
    - *户型图设计*：点位标注图（默认，叠加编号点位 + 品类图例 + 编号点位清单）/ 原图对照（左原始户型、右效果图叠加点位）/ 单张效果图（纯展示，不含设备标注）
    - *产品放置*：编号 + 名称（默认，徽章写编号，可与清单逐条对照）/ 产品图 + 名称 / 色点 + 编号
    - 编号在三套标记样式下统一为「清单顺序 + 1」，图上徽章与清单编号**严格一致**；点位超过一页容量自动**续页**并标明「共 N 台设备」，**绝不截断** —— 少列一台等于那台设备装不装没定
    - 改模版会 bump 版本号并让「已逐页校对」失效（交付件变了，旧的校对结论不再成立）
  - **页序唯一来源**：PPTX / 完整讲稿 / 免登录分享页 / 门店预览四处共用同一份页序（含户型页与点位清单续页），页数与页序不会各算一遍而对不上
  - **场景视频**：可把「AI 生视频」出好的片挂进方案（最多 2 条），分享页内联播放且置于幻灯片之前；**刻意不做方案页现场生视频** —— 模型是客户自备的
  - **多人协作安全**：保存单页时带版本号，期间若有人改过则 409 并提示重新载入，不会静默覆盖同事的修改

### 智能百宝箱（工具集）
- **产品中心**：侧栏「AI 能力」直达，公共产品库 + 我的产品库双 tab，搜索 / 分类 / 品牌筛选、新增 / 编辑 / 删除（仅我的库）、公共库一键**复制到我的库**；**39 预置品类字典**（网关中枢 / 网络覆盖 / 开关控制 / 中控面板 / 环境传感 / 人体存在 / 水浸 / 温湿度 / 灯光 / 窗帘 / 门锁 / 摄像 / 报警 / 家电 / 厨卫 / 扫地机 / 晾衣 / 音响 / 投影 / 暖通 / 循环扇 / 灌溉 / 宠物 / 插座 / 电视 / 冰箱 / 灶具 / 卫浴 / 门禁 / 门铃 / 音响面板 / 健康 / 适老 / 婴童 / 净化 / 加湿除湿 / 能源光伏 / 私有存储）覆盖市面主流品类，支持**自定义分类**（图标 / 颜色可选）；**每个产品都可上传自己的 PNG / JPG 主图**（自动压缩至 1024px，公共库行亦可直接「传图」），**产品图即点位图标**（lucide ISC 开源图标库线条图标，有图点位显示产品照片、无图回退品类图标）；勾选产品后**「AI 批量处理」**由智能体补全缺失的品牌 / 型号 / 布置提示、按品类字典归位分类并批量生成白底产品主图（单个失败不阻塞、留痕可查）；**知识库联动**——「内容提取」确认的产品资料自动同步到我的产品库（价格解析 + 品类推断），报价 / 点位 / 方案选品全联动
- **智能设备点位布局**：上传户型图（自动压缩）→ 一键**美化图纸**（白底增强，保持真实户型不变）→ 从产品库（公共 + 我的合并，39 品类**各配 lucide 线条图标**）点选布点 → 拖拽微调 → 导出标注图纸 PNG + 设备清单 CSV → 挂接方案空间动线页（预览 / PNG / PPTX / 分享页四端同一份合成像素，**点位为产品照片或品类图标徽章**）
- 三模式编辑器：设备点位 / **灯光点位效果图**（暖光光晕 + 图标）/ **WiFi 信号热力图**（网关为热源，红强绿弱叠加 + 图例）
- **智能灯光场景演示**：上传效果图 + 选画幅 → 编排灯具（吸顶灯 / 射灯 / 灯带 / 落地灯 / 台灯，图上拖动移位、改类型、上下调序、增删、设常暗）→ 手工灯光时间轴（每盏灯一条轨道，关键帧调亮度与色温，可播放预览）→ 以参考图为首帧出片；编排结果落库可复用，预览与出片共用同一份数据
- **智能报价**：产品库选品配单、数量步进、参考价区间实时算价、导出报价单 CSV（含"实际以门店方案师现场确认为准"合规说明）
- **问题反馈**：任意角色（含只读成员）都能提交故障与建议，管理员在同页回复并按 待处理 → 处理中 → 已解决 → 已关闭 流转，处理进度对提交者可见；仅提交者本人可删除

### 内容与资料
- 三源内容提取管道：文档上传（PDF / Word / 文本）/ 网页 URL / 语音纪要 → 结构化字段抽取 → 人工确认入库
- 我的知识库：上传企业资料、启用开关（供智能体优先参考）；**外部知识库联动**——客户本机部署 [WeKnora](https://github.com/Tencent/WeKnora)（腾讯开源 RAG 引擎）或 Obsidian（Local REST API 插件）后，平台经 REST 实时检索，让对话 / 接单 / 方案生成等所有板块的 AI 优先参考你的资料（在线配置、连通测试、检索演示、权限隔离与审计留痕）
- 我的作品：按分类（图片 / 视频 / 方案 / 文案）与日期分组的产物库，可下载复用；文件缺失自动降级"原文件暂不可用"占位
- 素材库：同行投稿的优秀素材浏览与解锁下载（按平台内额度计、同一条只解锁一次；**本部署不提供在线支付，扣的是用量统计不是货币**）；「我的投稿」当前仅有 Tab 与空态，投稿提交通道尚未接入
- 首次登录自动弹出使用说明（每用户仅一次，顶栏可随时再看）

### 接单工作台（AI 接待）
- 粘贴客户微信原话 / 电话纪要，AI 自动解析建档并按需求从产品库推荐关注品类与候选设备
- **结构化采集**（下游方案与报价的唯一输入，不靠自由文本猜）：客户与房屋（含装修阶段 6 档）、生活需求细分（常住成员 / 优先需求 ×3 / 明确不做 / 控制习惯 / 睡前夜间 / 已有设备偏好）、**客户想体验的 10 个场景**、**9 类系统的三态矩阵**（是否需要 + 应用区域 + 具体配置）、**预算起点 / 上限 / 包含范围**。AI 解析会一并抽取这些结构化字段，但**未提及的系统一律不猜**
- 状态机推进：了解客户 → 需求确认 → 方案匹配（可挂接已生成的智能方案）→ 报价 → 成单 / 失单（可重新激活），非法跳跃被拒绝
- 跟进记录时间线 + AI 跟进建议（下一步动作与话术要点），接待列表按状态分组持久化

- 全站**流式响应式**（768 → 1440 → 1920 → 4K 2560+）：内容区卡片随视口等比拉宽铺满，**不设固定封顶、不出现两侧大片留白**；功能页统一 PageHeader + 双栏卡片网格布局标准；界面图片资产本地化，无外部链接依赖
  - 实现要点：双栏页面的**主区容器必须显式 `flex: 1` + `minWidth: 0`**。在 AntD `Layout` 的 flex 行里，缺少 `flex-grow` 的容器会退化成内容宽度，视口多出来的部分全部变成右侧空白；`minWidth: 0` 则保证 flex item 能收缩到内容宽度以下而不是被内容撑开
  - 窄栏用**像素**而不是断点百分比：AntD 栅格 `lg={7}` 是固定比例，1920px 下左栏会占到 29%（约 472px），比窄栏设计意图宽出一倍

### 自己构建

```bash
pnpm install
pnpm --filter @app/desktop icons          # 生成图标（首次）
pnpm --filter @app/desktop dist:mac       # 出 .app / .dmg / .zip（已用 Developer ID 签名）
pnpm --filter @app/desktop verify:signature # 签名闸门：每个 Mach-O 的签名 + bundle 封印

# 公证（凭据在 ~/.symi/notary.env，权限 600）
source ~/.symi/notary.env && npm run notarize
```

`notarize` 会把 `.app` 提交 Apple 公证服务、等结果、把电子签章装订到 `.app` 与 `.dmg` 上，
最后挂载 dmg 复验里面的 app 仍带签章，再跑一次 Gatekeeper 评估。产物在 `apps/desktop/release/`。

> **公证前必须过签名闸门**：`verify:signature` 检查「每个 Mach-O 都用 Developer ID 签名」
> 和「bundle 封印有效」。第二项尤其关键 —— 桌面端有 Prisma CLI 与 jiti 两处会往
> **已签名的 app bundle 内部**写文件，破坏封印后 Apple 会直接拒收（本地验签却看不出来）。
> 细节见《桌面打包方案.md》第十一节。

> **要留出时间**：`.app` 压缩后 266MB，要整包传到 Apple 的云端。
> 国内直连上行通常只有几百 KB/s，**单次上传约 25 分钟**，两次（app + dmg）就是近一小时，
> 链路抖动还可能中断重传。跨境网络慢时可先设代理：`export HTTPS_PROXY=http://127.0.0.1:7890`。

### 桌面端的已知边界

- **只出 macOS arm64**：argon2 官方预编译没有 darwin-x64，Intel Mac 需要另行解决
- **Windows / Linux 未出包**：配置已按跨平台写好，但本机没有对应环境，**没有实跑过**
- **无自动更新**：换新版本重新下载安装包即可，数据不受影响
- **没有 pgvector 扩展**：当前 schema 不使用向量列，不影响功能

### 构建期网络配置

项目 `.npmrc` **刻意不固定 registry**，默认走官方源 `registry.npmjs.org`——这是 CI 与海外部署的正确选择。
国内网络构建慢或偶发抖动时，用构建参数切到镜像源，**不需要改仓库任何文件**：

```bash
NPM_REGISTRY=https://registry.npmmirror.com/ docker compose up -d --build
```

该变量由 compose 的 `build.args` 透传给 Dockerfile 的 `ARG NPM_REGISTRY`，仅作用于构建期，不进镜像、不影响运行时。

除此之外已内置三层防护，无需额外配置：

| 防护 | 作用 | 实测依据 |
|---|---|---|
| 网络退避重试 | registry 抖动（`error 23` / `ECONNRESET`）时自动重试 5 次，退避 20s→120s | 原故障即此类，重跑即恢复 |
| BuildKit pnpm store 缓存 | 依赖持久保留，重建时命中缓存不必全量重下 | 二次构建 258 个包**全部复用、零下载**，26.9s vs 冷构建约 2min |
| 供应链发布窗口 `minimumReleaseAge: 1440` | 新发布版本需满 24 小时才可安装，压缩投毒窗口 | 784 个条目全部通过校验 |

> `minimumReleaseAge` 取 24 小时而非 7 天是实测结论：本项目 Vite 8 / Rolldown 迭代极快，
> 7 天窗口会拒掉 `@rolldown/binding-*` 1.2.13、`@napi-rs/canvas` 1.0.11 等近 7 天发布的包并**直接打断构建**。
> 未设 `minimumReleaseAgeExclude`，即没有无效豁免；日后安装刚发布的版本会被明确拦下并提示。

## 开源定位：不做付费墙，额度只用来「看得见」

有些同类产品会把功能锁起来逼付费（测试账号只能试用 3 个智能体、点别的弹窗劝你充值）。
**本项目明确不做这一套**，理由很直接：开源项目一旦锁核心能力，采用者会直接转向，
反而违背了「逆向开源给所有智能家居伙伴用」的初衷。

所以这里的规则是：

| | 做法 |
|---|---|
| **能力** | **一律不锁**。额度不足只会暂停 AI 生成调用；资料库、方案、报价、点位、接单、团队、Agent 接入等全部照常可用 |
| **额度** | 由**部署者自己设定**（`BILLING_*_TOKENS`），并在后台按账号发放。它的作用是让部署者**看清成本、避免误用**，不是限制用户 |
| **计费单价** | 平台不预设商业价格。参考口径 `100 token = ¥1` 只是展示层换算，实际按你自己的模型成本设 `BILLING_*_TOKENS` |
| **数据** | 全部在你自己的机器上。额度、账本、审计、快照都在本地 PostgreSQL，可随时导出 |

「额度透明」在这里的具体含义：**每一个 token 花在哪一笔都进账本**
（`TokenLedger`，含 kind、消耗数、操作人、时间），账本可导出 JSON。
不透明的地方只有一个——模型服务商那边花了多少，只有你比我们清楚。

> 如果将来提供**官方托管版**，锁的会是便利项（自动备份、优先队列、多门店合并、
> 托管更新），**不会是任何核心能力**。自部署版永久免费无上限。

## 知识库联动：优势与场景

客户电脑性能足够时，可拉取最新仓库自行部署专业知识库引擎（[WeKnora](https://github.com/Tencent/WeKnora)：git clone → docker compose up -d；Obsidian：安装 Local REST API 插件），在「我的知识库」页填地址与 Key 即可联动。相比平台内置的轻量资料库，外部引擎带来：

- **更强的检索**：WeKnora 提供向量 + BM25 混合检索、GraphRAG、多文档格式解析（PDF/Word/Excel/图片 OCR），Obsidian 直读你的全部笔记库——资料规模越大、格式越杂，优势越明显
- **对话更准**：工作台对话自动检索客户私有资料注入上下文，回答引用你的产品手册与话术，而非通用模型泛泛而谈
- **接单更懂行**：AI 解析客户描述时能命中你资料库中的品牌、型号与报价规则，建档即带业务口径
- **数据主权 + 零锁定**：知识只存在客户自己的引擎里，平台仅经 REST 实时检索、不落副本；检索失败自动降级为无知识库模式，绝不阻塞主链路；每次检索写审计日志（场景 + 命中数），权限按租户与角色隔离

## 数据安全与并发保护

自部署场景最常出问题的三件事，这里都做了显式处理。

### 全库备份 **与恢复**
- `GET /api/admin/backup` 导出 33 张业务表的全量 JSON，同时在 `uploads/backups` 留一份并**自动裁剪到 3 份**
- `POST /api/admin/backup/restore` 从该 JSON 恢复，两种模式：
  - **合并**（默认）：按主键 upsert，**不删**本库多出来的行 —— 适合「误删了点什么，补回来」
  - **覆盖**：先清空目标表再写入，等于回到备份那一刻
- 安全措施：破坏性操作必须带确认串、只接受清单内的表名（上传的 JSON 不能决定往哪张表写）、
  单行坏数据不毁掉整次恢复、动作写入审计
- **备份只覆盖数据库**。产物文件在 `uploads` 卷，迁移时要连同数据库卷一起备份

### 提交幂等：同一个操作不会被执行两次
弱网超时后重试、跨标签页重复提交、手抖连点 —— 同一个 `clientRequestId` 只真正执行一次。

| 端点 | 机制 |
|---|---|
| 方案生成 / 生图 / 生视频 / 局部重绘 | 业务表带 `clientRequestId`，重放直接取回既有产物 |
| 产品 AI 批量 / 灯光问诊 / 接单接待 / 跟进建议 | 统一幂等表 `(tenantId, key)` 唯一约束抢占 |
| 素材购买 | 按标题查重，同一素材只解锁一次 |

失败的执行会**释放占位允许重试**（这一点与「卡住时禁止重新提交」相反：
后者只适用于异步出图队列，避免重复下单给供应商；同步端点失败就该允许重试）。

### 先出结果，再扣额度
生成类操作改为「**生成前只预检余额、生成成功才实际扣减**」。
重试三次全失败时用户**一分钱没花**；余额不足时 20 毫秒内直接拒绝，不调模型、不烧时间。

### 方案编辑乐观锁
`pages` 是整份 JSON 覆盖，两个同事同时改会互相抹掉。
保存时带版本号，期间若有人改过则 409 并提示重新载入，**不静默覆盖**。

## 安全、限流与数据治理

- 限流 env 可配：全局 `RATE_LIMIT_GLOBAL`（默认 300/分钟/IP）、注册 / 登录 `RATE_LIMIT_AUTH`（默认 10/分钟，防暴力破解）
- `trust proxy` 已开启，nginx 反代后限流按真实客户端 IP 计数
- 生产环境（`NODE_ENV=production`）：默认 JWT 密钥 / 默认管理员密码启动直接拒绝；Swagger 文档关闭
- 额度扣减在数据库事务内原子完成（`updateMany` 余额条件 + 账本写入），并发无超扣竞态
- 文件流路径穿越防护、上传 MIME + 大小校验、多租户资源隔离、密钥仅经环境变量注入不入库
- **数据备份**：个人设置「导出全库数据备份」→ `GET /api/admin/backup` 导出全部 28 表 JSON（同时在 `uploads/backups/` 留底）；产物文件在 `api-uploads` 卷、数据库在 `pgdata` 卷，迁移时连同两个 docker volume 一起备份即可完整恢复
- **磁盘治理**：`docker-compose` 已配 json-file 日志轮转（10MB×3）防日志挤爆磁盘；产物配额 `UPLOAD_QUOTA_MB`（默认 4096），个人设置可查看占用并一键清理 30 天前且未被方案/布局引用的过期产物
- **升级不丢数据**：数据全在 `pgdata` / `api-uploads` 两个命名卷，`docker compose up -d --build` 重建镜像不影响卷；nginx 对 `index.html` 禁缓存（hash 资源 immutable），发版后浏览器不会加载到失效 chunk

## Agent 机器接入（不用看界面就能操作系统）

面向 AI Agent / 自动化脚本的一层：独立身份、能力清单、全量审计、操作前快照与还原。

**1）身份**：独立服务账号 + 可撤销 API Key，权限完全走现有 RBAC

```bash
# 建机器账号（无可用密码，只能用 Key 登录）
curl -X POST http://127.0.0.1:3080/api/agent/service-accounts \
  -H "Authorization: Bearer <你的登录 token>" -H 'Content-Type: application/json' \
  -d '{"name":"数据分析 Agent","roleKey":"viewer"}'

# 签发 Key（只返回一次，平台不存密钥材料）
curl -X POST http://127.0.0.1:3080/api/agent/keys \
  -H "Authorization: Bearer <你的登录 token>" -H 'Content-Type: application/json' \
  -d '{"name":"ci-runner","ttlDays":90,"serviceAccountId":"<服务账号 id>"}'
```

Key 本身是一枚用 `JWT_SECRET` 签名的 JWT，库里只留可吊销的记录 —— **数据库整体泄露也推不出可用凭证**。
吊销：`POST /api/agent/keys/{id}/revoke`，立即生效。之后所有请求直接 `Authorization: Bearer <Key>`，
认证、RBAC、多租户全部沿用现成链路，**不需要为 Agent 单独开一套接口**。

**2）能力清单**：`GET /api/agent/manifest` 一次读懂全系统

| 取法 | 用途 | 实测量级 |
|---|---|---|
| `/api/agent/manifest` | 索引：分组 + 条数 + 破坏性操作数量 | **488 token** |
| `/api/agent/manifest?group=quote` | 只取报价这一组 | ~300 token |
| **`/api/agent/manifest?effective=1`** | **按调用者权限过滤，只列真正调得动的** | 视角色而定 |
| `/api/agent/manifest?risk=1` | 只取破坏性操作全表 | ~800 token |
| `/api/agent/manifest?full=1` | 全量 133 条路由 | ~3.4k token |

比让 Agent 读源码省一两个数量级的 token。**`effective=1` 是 Agent 的正确入口** ——
不按权限过滤的话，一个只读 Key 读到的清单也会显示「可以删产品」，Agent 就会照着错的预期
反复撞 403，既烧 token 又烧轮次。

清单由 smoke 门禁做**双向漂移检查**：
- 新增接口忘了写进清单 → FAIL；清单写了代码里没有的路由 → FAIL
- 每条操作都必须声明所需权限 → FAIL；声明的权限名必须真实存在 → FAIL
- **声明的权限必须与控制器里的 `@RequirePermissions` 装饰器一致** → FAIL（静态抽取比对，双向）
- **会扣额度的操作必须有权限声明** → FAIL（这条守卫抓出过一个真漏洞：
  `POST /api/media/materials/purchase` 扣 100 token 却没挂任何守卫，只读成员也能花租户额度）

**3）审计**：所有写操作自动落库

此前全项目只有 llm / layout / knowledge 三处手写记录，报价、接单、灯光、画布、方案一条都不记。
0.1.53 改由全局拦截器兜底 —— 靠自觉补是补不齐的，且以后每加一个 service 都会再漏一次。
每条记：谁（人点的 `USER` 还是机器跑的 `AGENT`）、什么时间、哪个接口、什么状态码、耗时多久、
请求体 SHA-256 摘要（**存摘要不存明文**，报价单与接单记录里全是客户姓名电话）。
客户端带 `X-Request-Id` 可把一串动作串成一次任务，用 `GET /api/agent/audit?requestId=...` 复盘。

**4）操作前快照与还原**

```bash
# 动数据前打点
curl -X POST .../api/agent/snapshots -d '{"label":"批量导入产品前"}'
# 出问题还原（confirm 必须是快照 id 前 8 位，防手滑调错快照）
curl -X POST .../api/agent/snapshots/{id}/restore -d '{"confirm":"<前8位>"}'
```

破坏性操作（DELETE、或清单里标 `risk=destructive` 的接口）在调用方没自带 `X-Snapshot-Id` 时，
**拦截器会先自动打一份 `auto` 快照再放行**，快照 id 记进对应审计行。
同一份快照不允许反复还原 —— 否则会把后续的正确操作一起冲掉。

> ⚠️ **能力边界，不要当万能后悔药**：快照只还原**数据库里的行**。
> 已经扣掉的额度、已由外部 API 生成出来的图片/视频、已发出的通知**撤不回**。
> 这句话在快照详情与 manifest 响应里都会显式返回，不做暗示性包装。
>
> 快照**刻意不含** `AuditLog`（还原它等于改写「谁动过」这段历史）与模型配置（部署级共享，还原会连别的租户一起改）。

## 团队、角色与局域网使用

侧栏「系统管理 → **团队与接入**」（`/team`）：人类成员、角色、机器账号与 API Key 都在这一页。

**角色 = 权限模板，不逐项勾**。本项目有 15 个权限 action，让店长逐项勾既容易配错也没人配得下去，
所以预置了 11 个按智能家居门店岗位划分的模板（超级管理员 / 租户管理员 / 销售顾问 / 设计师 /
施工交付 / 财务 / 采购仓管 / 市场运营 / 客服售后 / 运营 / 只读成员），点一下就能用。

**每个岗位都能做完自己那条线**。销售顾问这条线是「接待客户 → 出方案 → 报价 → 接单」，
所以销售顾问与运营都带「做方案」权限（能看方案、能建方案、能上传户型图、能渲染精装图）；
财务 / 采购仓管 / 客服售后 / 只读成员不带 —— 岗位用不到，权限不必给宽。

**模板不够用就自己勾一个**。点「自定义角色」，权限按业务分组呈现（报价 / 内容 / 知识库 / 协作 /
团队 / 平台），显示的是「报价与产品库」这类人话，不是 `platform:billing:manage` 权限串。

> ⚠️ **防提权**：只能授予自己已经拥有的权限 —— 你能给出去的，永远不会比你手上的多。
> 界面把没有的权限直接置灰，服务端再挡一道 `PRIVILEGE_ESCALATION`。
> 没有这道守卫，任意「能管成员」的角色都能造一个含 `platform:*` 全权限的角色塞给自己，
> 权限体系整个击穿。

其他约束：还有成员在用的角色不能删；系统模板不可改/不可删；最后一个管理员不能被降级或移除。

**局域网使用**：主账号在这台电脑上操作；团队成员用浏览器打开 `http://<主机IP>:5173`
登录自己的账号即可访问同一套数据，不会用的功能直接问 Agent。

> 局域网访问**不受 CORS 限制** —— nginx 把 `/api` 同源反代到 api 容器，浏览器只看到一个源。
> CORS 只影响本地开发（vite 5173 直连 api 3080 跨源）。

**顶栏的额度胶囊与「开源说明」按钮默认隐藏**（开源免费自部署下这两项没有实际意义，
额度胶囊容易被误读成「要先充值才能用」）。需要看账与看说明的人在
「个人中心 → 资料与偏好」打开开关。侧栏没有「会员」入口，页面名与路由也都不带该字样。

**Agent 的权限边界**：机器账号也有角色。Agent 先读 `?effective=1` 清单就知道自己有哪些能力，
不必反复撞 403 试错。跨租户访问会被 `API_KEY_TENANT_MISMATCH` 明确拦下。

## 开发规范

- 回复与注释使用中文，不使用 emoji
- 决策阶梯：YAGNI → 复用 → 标准库 → 原生 → 已装依赖 → 一行 → 最少实现
- 提交前必须：`pnpm typecheck && pnpm build && pnpm smoke` 全绿
- 新增依赖需许可证检查（MIT / Apache-2.0 / BSD 优先，禁止 GPL / AGPL）

### 关于「完成」的判定口径

`smoke` 只证明 **HTTP 契约**正确（校验、权限、幂等、落库、参数是否真正传到出图层），
**证明不了界面**。本项目曾因此把「开始接单」标成完成，实际缺了 5 处结构化采集，
而 222/222 全绿、typecheck 全过、数据层完全正确 —— 三道门禁全部看不出来。

因此本仓库统一：

- 功能矩阵里的 `✅` 只代表**已打开界面逐屏核对通过**；仅代码 / 契约层面确认的一律标 `🔸`
- 改任何影响界面呈现的代码前**必须先截图取证**；截图不可信时以 DOM 的 inline style 为准
  （本机浏览器截图工具出现过复用同一帧缓存的情况，连续多帧字节完全相同）
- 每轮迭代的逐板块核对结论落在 [`replica/audit-2026-10-13.md`](./replica/audit-2026-10-13.md)，
  含**未验证项**与**验证方法的边界**，避免下一个人拿可疑证据下结论

## 路线图（未交付，诚实标注）

**明确没做的，以及为什么：**

- **逐页 AI 出图队列**（出图队列 + 6 态状态机 + 仅补齐失败页）。方案页配图目前用
  5 张内置实景图。逐页出图等于每次交付都要按页调生图模型，成本与等待都不划算，
  而门店真正在意的是「这份方案是给我这个客户做的」——靠上传的效果图与设备点位已经能表达。
  真要做，建议只出**关键页**（封面 / 动线 / 2~3 个核心场景），而非逐页全出
- **逐页圈选重画 / 换图 / 单页恢复**：依赖上一条，没有逐页出图就没有「重画」的对象
- **LiteLLM 网关统一路由**（当前默认直连 MiniMax / OpenAI 兼容 / ComfyUI）
- **尾帧控制**：MiniMax 第一代 `T2V/I2V-01` 仅支持首帧；尾帧需换 H3 等支持首尾帧的模型，
  模型名可在「模型配置」指定但参数档位未逐一实测
- **MiniMax 语音合成 / 音乐生成 / 音色克隆**（官方接口已确认可用，本项目尚未对接）
- **按遮罩的局部重绘目前仅 OpenAI 兼容通道可用**（`images/edits`）；MiniMax 图像接口无 mask 参数，
  其 `subject_reference` 是参考图主体一致性、语义不等价，故不做静默降级
- **知识库改用向量检索**：当前是本地二元组（bigram）中文检索，实测相关问题得分 2.6~10.6、
  无关问题精确返回 0，且不依赖 embedding API（门店伙伴未必配 key，也不必联网付费）。
  资料量涨到百万字级、检索成为瓶颈时再换 pgvector（镜像已自带扩展）不迟
- **邀请返点自动结算**（角色权限、共享额度已就绪，缺的是结算流程）
- **IoT 联动 / 客服工单**
- **运营后台、英文 i18n**
- **多端打包本地安装**（Electron / Tauri 桌面壳复用现有 Web 产物，升级不影响 pgdata / api-uploads 卷数据）

**参考站有、本项目有意不做的**：会员 / 套餐 / 充值分级、素材市场的人民币分成。
与「完全免费自部署」定位冲突，详见「开源定位」一节。
